# 中秋禮盒訂單整合與統計工具

暑期資訊助理工作期間開發的 Windows 桌面應用，整合網站 WMS、ERP、POS 與手開訂單 Excel，產生商品數量、叫貨日期與到貨日期統計表，減少人工逐筆核對與計算。

## 專案背景與成果

原有流程需要同事從多個系統取得訂單，再人工整理商品、數量與日期。不同來源的商品名稱、資料格式與日期表示方式不一致，使彙整工作需要反覆確認。

| 項目 | 原有流程 | 導入工具後 |
| --- | --- | --- |
| 作業人數 | 2～3 人 | 1 人 |
| 每次耗時 | 1 小時以上 | 半小時內 |
| 處理方式 | 跨系統逐筆核對與計算 | 載入來源資料、自動產生統計表，再人工審核少數異常訂單 |

以上為暑期工作中的實際作業觀察，非標準化效能測試。

## 我的角色與 AI 開發分工

本專案使用 Codex 進行 AI 輔助開發，程式碼由 AI 撰寫。我主要負責：

- 訪談使用部門，理解原有流程與作業痛點。
- 整理不同來源的欄位、商品識別與日期計算規則。
- 透過具體案例確認需求，並引導 AI 調整功能。
- 測試輸出結果，核對正常資料及例外情況。
- 教同事操作工具，依使用回饋持續修正。

此作品呈現我在需求分析、資料規則整理、測試與使用者溝通上的實務經驗。

## 主要功能

- **多來源整合：** 串接兩個 WMS API，並匯入 ERP、POS 與手開訂單 Excel。
- **商品識別：** 以穩定商品識別值比對，降低商品名稱差異造成的分類錯誤。
- **日期處理：** 解析多種日期格式及日期區間，依規則計算下單與到貨日期；無法判定的資料交由人工確認。
- **Excel 匯出：** 產生「訂單明細」「日期待確認」「統計」「本次補單」四張工作表，使用 Excel 2013 相容公式進行統計。
- **人工覆寫：** 保存使用者確認的日期與地點等欄位，重新匯入後仍保留人工調整。
- **差額比對：** 比較本次與上次正式送廠資料，呈現新增、減量與取消造成的數量差異。
- **同步與復原：** 分離暫存與正式快照，保留跨重啟資料及匯出中斷復原機制。
- **測試匯出：** 預覽結果而不更新正式送廠基準。

## 開發過程中的問題與處理

### 不同來源的商品名稱不一致

在 API 回傳的 JSON 中找到可穩定識別商品的值，改用商品識別值建立對照，讓品名文字變動不影響正式分類。

### 日期格式與作業規則不同

支援多種日期格式與日期區間，並將無法解析或互相衝突的資料列入待確認清單。保留人工審核流程，避免猜測日期造成錯誤排程。

### 需求需要反覆確認

使用部門並非資訊背景，初期需求需經多次調整。我透過具體資料與輸出結果確認規則，再把回饋轉成可測試的案例，逐步對齊實際作業流程。

## 建置與執行

### 環境

- Windows x64
- .NET 8 SDK（從原始碼建置時）
- 實際 WMS 使用需要有效的 API 憑證與相應存取權限。

在專案根目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

腳本會還原套件、執行核心測試，並將自包含的 Windows x64 程式發布至 `build/publish/`。

執行 `build/publish/中秋禮盒-WMS預覽.exe`，設定各來源憑證、取得訂單並匯入 Excel，確認預覽後匯出統計表。

若只要執行核心測試：

```powershell
dotnet run --project tests/MidAutumnGiftBox.Core.Tests/MidAutumnGiftBox.Core.Tests.csproj
```

## 資料與憑證處理

API Key 由目前 Windows 使用者的 Credential Manager 保存，不硬編碼於程式。WMS 收件人姓名、電話、地址及相關密文不納入正式訂單快照與 Excel 輸出。來源備註可能含個資，使用者仍需檢查實際匯入資料及展示內容。

## 目前限制

本專案依原作業情境設計，商品與通路規則尚未提供完整的使用者設定介面；也尚未涵蓋跨電腦共用資料的鎖定與同步。直接建置不代表可以連線至實際 WMS，仍須具備有效憑證與授權。
