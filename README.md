# 中秋禮盒 WMS 資料預覽

第一階段桌面程式，用於連接兩個 WMS、保存各自憑證，以及預覽店舖與待處理訂單資料。

## 使用方式

1. 執行 `build\publish\中秋禮盒-WMS預覽.exe`。
2. 選擇網站1或網站2。
3. 輸入該網站的 API ID 與 API Key。
4. 按「安全保存憑證」。API Key 會存入目前 Windows 使用者的 Credential Manager，不會寫在程式或共用槽。
5. 按「取得店舖清單」測試連線並查看整理後表格；安全 JSON 頁籤已移除。
6. 按「重新載入完整訂單」。程式會自動先驗證店舖，再以訂單成立日從 2026/07/01 完整查到本次開始日；兩站都取得且驗證成功後會一起保存為「尚未正式匯出」的暫存快照，任一站失敗時不改變既有正式快照。暫存快照可跨程式重啟保留，並優先顯示在預覽畫面。
7. 可在「ERP」頁籤選擇 ERP 產出數量 Excel、「手打單」頁籤載入手打單 Excel，或在獨立的「POS機」頁籤選擇百貨專櫃預購報表。POS機不是 Flavor 網站內的 POS 通路；重複載入會取代本次執行中的同類預覽，不會加倍。
8. 完成後按「匯出／更新禮盒 Excel」。這次正式匯出即視為送廠，活頁簿包含「訂單明細、日期待確認、統計、本次補單」四張工作表；訂單明細依來源、訂單編號、標準品名與指定到貨日逐筆列出。「統計」按「下單日＋到貨日＋地點」分列，固定包含八個商品欄；顯示鍵、列清單與數量全部由 Excel 2013 相容公式產生，數量使用原生 `SUMIFS`，空白地點顯示為「未設定」，不另設合計欄。使用者修改訂單明細日期後，Excel 開啟時計算即可反映至統計。
   「本次補單」使用相同的下單日、到貨日、地點及八個商品欄，以「本次正式送廠快照－上次正式送廠快照」顯示差額；增加為正數、減少為負數、零差異不列出，不另設狀態欄。若本次和上次完全相同，工作表只會留下標題列；第一次使用新版正式匯出時沒有舊基準，因此目前全部數量會顯示為正數。
   程式輸出儲存格統一使用標楷體，不自動建立 Excel 篩選。
   地點空白時會依來源及固定通路對照補入：網站的正-新光A4、臨新莊宏匯、臨桃園大江、正-京站、臨大葉高島屋、臨新竹大全聯、正-台中高鐵、正-夢時代、臨新光三越台南新天地、YAHOO、阿瘦、PCHOME 及 i預購為「彰廠」；POS機資料一律為「躉泰」。手打單 Excel 的「地點」是自訂文字，會完整保留，不限制為固定廠商。
9. 程式會在每次匯出前讀回最近正式 Excel 的「指定到貨日、下單日、地點、確認」。只要和上次匯出值不同，就永久保存為人工覆寫；刻意清空也算人工值。若舊檔遺失，程式會要求放回原路徑，並提供改選舊檔、確定匯出或取消。
10. 按「清除人工覆寫」可選擇一筆訂單明細，經警告確認後一次清除該列四個人工欄位；下次匯出恢復最新來源與自動規則。人工覆寫檔及最近正式 Excel 路徑不受重新載入完整訂單影響。
11. 「手打單」頁籤只提供手打單 Excel 選檔。逐筆新增與切換登記狀態功能已移除；既有本機逐筆手打資料保留於原處，但不再加入匯出。
12. 「測試匯出（不保存）」會以目前預覽及已保存的人工覆寫建立一份全新的測試 Excel，並預覽相對於上次正式送廠快照的「本次補單」。它不允許覆寫既有檔案，也不更新送廠比較基準、上次正式 Excel 路徑、人工覆寫、正式快照或待提交的暫存快照；在非星期二／四開啟程式做測試不會因此遺失訂單。

### 固定檔名自動載入

將 `auto-import.cmd`、`MidAutumnGiftBox.exe` 與以下三個檔案放在同一資料夾，再執行 CMD。正式發布資料夾會同時保留原本的中文 EXE 名稱：

- `ERP產出數量.xlsx`
- `蛋黃酥-數量.xlsx`
- `百貨專櫃門市預購報表.xlsx`

程式開啟後會依序載入三個固定 Excel、使用已安全保存的兩站憑證重新取得完整網頁訂單，最後輸出同資料夾的 `中秋禮盒訂單統計.xlsx`。既有正式 Excel 及已保存的人工修改會保留；快速流程不會清除人工覆寫。

快速流程要求三個固定 Excel、兩站憑證與兩站網頁查詢全部成功。任一檔案缺少或格式錯誤、任一網站失敗、或匯出失敗時，都會停止且不產生新版正式 Excel，以免使用不完整資料。

「日期待確認」欄位為：通路別、品名、指定到貨日、數量、確認、地點、訂單編號、備註。使用者只填「指定到貨日」，不顯示也不填下單日；日期必須是有效的 Excel 固定日期且為星期二或星期四。下次匯出／更新時，程式讀回日期並永久保存成人工覆寫，自動計算下單日為 7 天前，該列隨即移到「訂單明細」。文字、公式、無效日期或非星期二／四日期會拒絕並顯示原因，不會靜默調整。清除該列人工覆寫後，如果來源仍無日期，資料會回到「日期待確認」。舊版九欄日期待確認工作表可在下一次更新時自動升級為此格式，既有確認與地點仍保留。

每次載入訂單後，畫面會按來源顯示最近同步結果、查詢日期、完成分頁、筆數及最後成功時間。摘要保存在目前 Windows 使用者的本機應用程式資料目錄，只含同步狀態，不含訂單 JSON、API ID、API Key 或 Token。失敗會留下安全錯誤摘要，但不會清除先前的最後成功時間。

完整載入成功後，程式會把整理後的父商品與子商品欄位展開保存為本機暫存快照；只有正式 Excel 建立成功、可讀回且人工覆寫狀態也保存成功後，才把該次暫存資料提交為正式快照。相同資料重跑不會重複，數量或狀態變更會更新，已不在目前 `status=F` 完整結果中的訂單會移除。若 Excel 已完成但正式快照提交中斷，程式會保留交易標記並在下次啟動時復原，不會直接載入另一批資料覆蓋。WMS 的收件人姓名與電話採 AES-128-ECB 加密，且必須使用後台另一組個資解密金鑰；本程式只使用 API ID／API Key，因此不保存或輸出姓名、電話、地址及密文。

畫面與匯出會優先使用尚未正式提交的暫存快照；沒有暫存資料時才使用目前正式快照。不再讀寫追加式 Ledger，也不查詢已離開待處理頁面的訂單狀態。安全遮罩處理仍保留在底層，但不再提供 JSON 顯示頁籤。程式重新啟動或切換來源時仍可查看暫存或正式訂單；最近一次完整載入失敗時保留原有資料。

訂單同步會送出 `date_min=2026-07-01`、`date_max=本次開始日` 與 `status=F`，逐頁取得待處理訂單。訂單成立日只用來限制載入範圍；程式不以 `arrival_date` 篩選，空白或格式異常仍會列出並保留原值。API 文件沒有 `arrival_date` 查詢參數，因此程式不會送出未定義的到貨日條件。

兩來源載入時優先保留父商品或 `items` 子商品命中八個固定 `item_no` 的訂單；既有名稱含「蛋黃酥」或指定 SKU 條件仍保留，讓 item_no 尚未綁定的異常商品可出現在預覽供查核。正式 Excel 只依固定 item_no 分類：有目標子商品時，每個不同 item_no 分列並使用該子商品 qty；同一父商品內相同 item_no 的多列先加總。沒有目標子商品時，才使用父商品本身的 item_no 與 qty。父子皆無目標 item_no 時只留在預覽，不以名稱、spec 或 SKU 猜測正式品項。

WMS 的單顆料號 `1902199`、`192199`、`1902072` 採依附日期規則：單顆有自己的有效日期時直接保留；單顆無日期但同訂單含禮盒時，繼承該訂單所有有效禮盒中最早的日期；同訂單有禮盒但所有禮盒日期都無法判定時，單顆仍進「日期待確認」。只有單顆同時「無日期且同訂單無禮盒」時才排除正式 Excel。可提供日期的禮盒料號為 `1902226`、`1902197`、`1902248`、`1902247`；`1902042` 三入條裝不作為禮盒日期來源。

睿驛的 `source` 是賣場名稱，`source_key` 才是通路代碼。程式將 `source_key=shopee` 顯示為「蝦皮賣場」，並另存原 `source` 為賣場名稱。商品文案若含明確日期區間，先以區間內星期一（沒有星期一時為第一個工作日）作原定日期；API `arrival_date` 也可作原定日期。指定到貨日由原定日期往前取最近的星期二或星期四（原日已是星期二／四則不動），下單日固定為指定到貨日前 7 個日曆日、同一星期；例如原定 2026/08/15 會得到指定到貨日 2026/08/13、下單日 2026/08/06。例外：WMS `site1/site2` 的正-新光A4、正-台中高鐵、臨新竹大全聯、正-夢時代、正-京站、臨新莊宏匯、臨桃園大江、臨大葉高島屋、臨新光三越台南新天地，先將來源原定日期減 1 個日曆日，再往前調整至最近的星期二／四；ERP、POS、手打單及其他 WMS 通路不適用此例外。

ERP 與手打單 Excel 均以八個固定料號精確篩選：`1902199`、`192199`、`1902072`、`1902042`、`1902226`、`1902197`、`1902248`、`1902247`。其他 ERP 料號不進入正式 Excel，並計入排除筆數。ERP 與手打單的「備註」欄會原樣顯示於預覽並匯出至正式 Excel。ERP 訂單地點預設為「彰廠」；若既有正式 Excel 已人工修改地點，仍以人工值優先。

正式 Excel 保留目前來源資料中的全部日期，不再依今天排除過去訂單；統計公式同樣計入過去、今天與未來日期。日期無法判定的資料仍留在「日期待確認」。

兩網站訂單 API 的訂單層級 `note` 會保存為「備註」，並顯示於預覽及正式 Excel。ERP 與手打單讀取「備註」，POS機只讀取「系統內部備註」；欄位不存在或內容空白時留空。WMS 日期來源優先序固定為商品 `spec/name`、API `arrival_date`、訂單 `note`。備註只有一個明確日期區間時才作最後備援；多區間標記 `conflict`，明確區間格式錯誤標記 `needs_review`，不得猜測日期。例如美安備註「預計到貨日 8/29~9/4」在 2026 年會以 2026/08/31 作原定日期、指定到貨日為 2026/08/27、下單日為 2026/08/20。

百貨 POS機報表只依非空白 `貨號` 精確識別目標商品，完整保留 `訂單來源` 與來源品名，並將「系統內部備註」匯出為備註；先以 `預購取貨日` 前一天作原定日期，再調整至最近的星期二／星期四，數量採 `出貨數`。貨號空白時一律排除，即使 SKU 或品名含蛋黃酥也不補入；貨號正確時不因來源品名改字而排除，且沿用既有 POS 明細識別以保留人工覆寫。目前真實檔只接受貨號 `1902072` 的單入、`1902248` 的六入及 `1902247` 的九入，其餘列只計入排除統計。

POS 目標商品的「預購取貨日」空白時，以該「訂單編號＋貨號」第一次載入日固定排程：下單日取第一次載入當天或之後最近的星期二／星期四（當天符合即使用當天），到貨日為下單日加 7 天，備註固定為「未指定預購日」。同一明細隔日或日後重載不重新往後移；同一檔案後來新增的訂單明細則各自使用首次出現日。狀態保存於本機 `pos-first-import.json`，不受 WMS 完整重載或歷史重設影響。非空白但格式無法解析的日期仍拒絕整批 POS 載入並顯示警告，不得當成缺日期自動排程。

## 安全規則

- API Key、Bearer Token、Authorization、姓名、電話、Email、地址及收件資訊不會顯示在預覽 JSON。
- 收件人姓名、電話、地址及 API 密文不保存於本機快照或正式 Excel。
- 已保存的 API Key 不會回顯在畫面。
- 網站1與網站2的憑證分開保存。
- 每個 Windows 使用者需要在自己的電腦上保存一次憑證。
